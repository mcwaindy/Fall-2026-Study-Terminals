linux_processes/2_killing_processes.txt
=============================================
-----------------------------------------
1 	when there are a large number of rogue and zombie processes using resources, you should send them a kill signal
-----------------------------------------
2 	a kill signal terminates a process
-----------------------------------------
3 	the most command to send kill signals is the kill command.
-----------------------------------------
4 	the kill command can send many different types of kill signals, and each kill signal operates in a different manner.
-----------------------------------------
5 	use the -l option to view the kill signal names and associated numbers
-----------------------------------------
6 	most of the commands are not useful for admins. Here are the five most common kill signals:
-----------------------------------------
7 	NAME		NUMBER			DESCRIPTION
-----------------------------------------
8 	SIGHUP		1		AKA hang-up signal. Stops a process, then restarts it with the same PID. if you edit the config file used by a running daemon, the daimon might be sent this signal and read the new config file
-----------------------------------------
9 	SIGINT		2		Sends an interrupt signal to a process. One of the weakest, but works most of the time. CTRL+C is actually a SIGINT.
-----------------------------------------
10	SIGQUIT		3		AKA core dump. terminates a process by taking the process info im memory and saving it to a file called core on the FS in the current working dir. CTRL+\ key combination.
-----------------------------------------
11	SIGTERM		15		software termination signal. most common kill signal used by programs to kill other processes. Also the default used by the kill command.
-----------------------------------------
12	SIGKILL		9		AKA absolute kill signal. forces linux kernel to stop executing the process by sending the process's resources to a special device called /dev/null
-----------------------------------------
13	specify the kill signal to send as an option to the kill command, followed by appropriate PID of the process to send a kill signal
-----------------------------------------
14	example: to kill a process called sample
-----------------------------------------
15	ps -ef | grep sample (shows process)
-----------------------------------------
16	kill -3 1199
-----------------------------------------
17	ps -ef | grep sample (process is gone)
-----------------------------------------
18	if you do not specify the kill signal, the kill command uses SIGTERM, the default
-----------------------------------------
19	the pidof command can also be used to find the PID of a process to use as an arg to the kill command.
-----------------------------------------
20	the pgrep command returns a list of PIDs for processes that match a regex or other criteria, and is often easier to locate processes.
-----------------------------------------
21	example:
-----------------------------------------
22	pgrep -u bini "^psgl"
-----------------------------------------
23	returns a list of processes that start with the letters 'psql'
-----------------------------------------
24	some processes have the ability to ignore, or trap, certain kill signals
-----------------------------------------
25	the only kill signal that cannot be trapped by any process is SIGKILL
-----------------------------------------
26	however, you should only use SIGKILL as a last resort because it prevents a process from closing open files and other resources properly
-----------------------------------------
27	the lsof (list open files) command views the files that a process has open before sending a SIGKILL.
-----------------------------------------
28	if you send a kill signal to a process with children, the parent process terminates all child processes before terminating itself.
-----------------------------------------
29	killing a parent process is often necessary for zombies
-----------------------------------------
30	conversely, to prevent a parent from killing a child, you can start the child process with the nohup command.
-----------------------------------------
31	killall command can also kill processes. uses the process name instead of PID
-----------------------------------------
32	allows multiple processes of same name to be killed at once
-----------------------------------------
33	SIGTERM is still the default for killall
-----------------------------------------
34	the pkill command also kills processes by process name. allows you to identify process names using regex and other criteria
-----------------------------------------
35	example:
-----------------------------------------
36	pkill -u bini -3 "^psql"
-----------------------------------------
37	the top command can also be used to kill processes. while in utility, use the k key and supply the PID, then kill signal when prompted.

linux_processes/3_process_execution.txt
=============================================
-----------------------------------------
1 	You can execute three main types of linux commands:
-----------------------------------------
2 	# Binary Programs
-----------------------------------------
3 	# Shell Scripts
-----------------------------------------
4 	# Shell Functions
-----------------------------------------
5 	most commands are binary programs, exist on FS until executed. Written in a certain programming language and compiled into binary format. ls, find, grep.
-----------------------------------------
6 	other commands are built into the shell running in memory, called shell functions. cd, exit.
-----------------------------------------
7 	shell scripts can also contain a list of bin programs, shell functions, and special constructs for the shell to execute in order
-----------------------------------------
8 	when executing compiled programs or shell scripts, the shell that interprets the command you typed creates a new shell. This is known as forking.
-----------------------------------------
9 	carried out by the fork function in a shell
-----------------------------------------
10	the new subshell executes the binary program or shell script using its exec function. after completion, the new shell uses its exit function to kill itself and return control to the original shell
-----------------------------------------
11	the original shell uses a wait function to wait for the new shell to finish

linux_processes/4_running_processes_in_the_background.txt
=============================================
-----------------------------------------
1 	processes for which the shell that executed it must wait for its termination are called foreground processes
-----------------------------------------
2 	you can omit the wait function by appending an ampersand to the command
-----------------------------------------
3 	commands run in this fashion are called background processes
-----------------------------------------
4 	the shell immediately returns the shell prompt for the user to enter another command when a command is run in the background
-----------------------------------------
5 	example:
-----------------------------------------
6 	sample &
-----------------------------------------
7 	[1] 2583
-----------------------------------------
8 	the space between the ampersand is not required
-----------------------------------------
9 	the shell returns the PID and a background job ID so that you can manipulate the bg job after it has been run.
-----------------------------------------
10	you can use the ps or jobs commands to view the background job ID
-----------------------------------------
11	along with the PID, you can kill a bg process by sending a kill signal to the job ID. bg job IDs must be prefixed with a % char
-----------------------------------------
12	you can move a bg process to the foreground by using the fg command
-----------------------------------------
13	you can pause a foreground process with the CTRL+Z command, and then send the process to the background with the bg command.
-----------------------------------------
14	the CTRL+Z key combination assigns the foreground process a job ID that is then used as an arg for the bg command
-----------------------------------------
15	when there are multiple bg processes, the jobs command indicates the most recent one with a + symbol
-----------------------------------------
16	the second most recent has a - symbol
-----------------------------------------
17	using the % notation without an ID, it it will operate with the most recent bg process.

linux_processes/5_process_priorities.txt
=============================================
-----------------------------------------
1 	because most computers obtain only a single CPU, Linux executes small amounts of each process on the processor in a series.
-----------------------------------------
2 	time slice is the the amount of time a process has to use the CPU is called a time slice. The more time slices a process has, the more time it has to execute on the CPU and the faster it executes.
-----------------------------------------
3 	Time slices are typically measured in milliseconds. several hundred processes can be executing on the processor in a single second.
-----------------------------------------
4 	the 'ps -l' command lists the kernel priority (PRI) of a process. directly related to the amount of time slices a process has on the CPU.
-----------------------------------------
5 	A PRI of 0 is most likely to get time slices on the CPU, and a PRI of 127 is the least likely.
-----------------------------------------
6 	you cannot change the PRI directly, but you can influence it by assigning a certain nice value to a process
-----------------------------------------
7 	all users can be "nice" to a process and increase their nice value, but only an admin can lower the nice value.
-----------------------------------------
8 	processes are started with a nice value of 0 by default
-----------------------------------------
9 	to start, for instance, the ps -l command, with a nice value of +19, use the -n option:
-----------------------------------------
10	nice -n 19 ps -l
-----------------------------------------
11	if the process is already started, you can change its priority by using the renice command:
-----------------------------------------
12	renice +15 1990 2180
-----------------------------------------
13	you can also use the top utility to change nice values. Use the r key, then supply the PID and nice value when prompted.
-----------------------------------------
14	root user can use renice to change the priority of all processes owned by a certain user or group:
-----------------------------------------
15	renice +15 -u mary bini
-----------------------------------------
16	renice +15 -g sys

-----------------------------------------
3 	COMMAND			DESCRIPTION

5 	at 10:15pm July 15	schedules commands to run at 10:15 PM on July 15

-----------------------------------------
7 	at midnight		schedules commands to run at midnight on the current date
-----------------------------------------
8 	at noon July 15		schedules commands to run at noon on July 15
-----------------------------------------
9 	at teatime		schedules commands to run at 4:00 PM on the current date.
-----------------------------------------
10	at tomorrow		schedules commands to run the next day.
-----------------------------------------
11	at now + 5 minutes	schedules commands to run in five minutes
-----------------------------------------
12	at now + 10 Hours	schedules commands to run in ten hours.
-----------------------------------------
13	at now + 4 days		Schedules commands to run in four days.
-----------------------------------------
14	at now + 2 weeks	schedules commands to run in two weeks

19	after being invoked, the at command displays an 'at>' prompt. commands can be executed, one per line.
-----------------------------------------
20	after the commands have been entered, use CTRL+D key combination to schedule the commands.
-----------------------------------------
21	the atd daemon uses the current shell's env. stored in /var/spool/at directory on fedora systems or /var/spool/cron/atjobs on Ubuntu systems.
-----------------------------------------
22	because most distros do not ship with a mail daemon, it is important to redirect the output of any commands scheduled using atd to a file.
-----------------------------------------
23	example:
-----------------------------------------
24	==============================
-----------------------------------------
25	# at 10:15pm July 15
-----------------------------------------
26	at> date > /root/atfile
-----------------------------------------
27	at> who >> /root/atfile
-----------------------------------------
28	at> CTRL+D
-----------------------------------------
29	job 1 at Wed Jul 15 22:15:00 2023
-----------------------------------------
30	#
-----------------------------------------
31	=============================
-----------------------------------------
32	the at command returns a job ID. you can use this ID to query or remove the schedule command
-----------------------------------------
33	to see a list of at job IDs, you can specify the -l option to the at command:
-----------------------------------------
34	at -l
-----------------------------------------
35	for regular users, at -l output only shows their own shceduled processes; root user sees all schedules jobs at once.
-----------------------------------------
36	to see the ocntents of the job alongside the shell env at the time the job was scheduled, you can use the -c option with the at command and specify the job ID
-----------------------------------------
37	to remove the at job, specify the -d option followed by the appropriate job ID.
-----------------------------------------
38	if there are many commands to be scheduled using the at daemon, you can use a shell script and schedule the shell script to execute using the -f option.
-----------------------------------------
39	example:
-----------------------------------------
40	# cat myscript
-----------------------------------------
41	#this is a sample shell script
-----------------------------------------
42	date > /root/atfile
-----------------------------------------
43	who > /root/atfile
-----------------------------------------
44	# at 10:15pm July 16 -f myscript
-----------------------------------------
45	job 2 at Wed Jul 15 22:15:00 2023
-----------------------------------------
46	#
-----------------------------------------
47	=================================================
-----------------------------------------
48	if /etc/at.allow and /etc/at.deny files don't exist, only root user is allowed to schedule tasks with at
-----------------------------------------
49	to give ability to other users, create an allow file and add the names of users, one per line
-----------------------------------------
50	the deny file can deny certain users access. any user not listed in this file is allowed to use the at daemon
-----------------------------------------
51	if both files exist, the system checks the allow file and does not process the deny file
